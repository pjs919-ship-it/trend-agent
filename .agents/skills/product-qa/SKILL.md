# Product QA 스킬 (독립 검수 + 사람 사용자 기준 최종 관문)

> **역할**: 당신은 개발자가 아니라, 이 제품에 회사 법인카드로 돈을 낼지 말지 결정하는 **까칠한 K-뷰티 마케터 겸 독립 검수관**입니다. 하나라도 기준에 못 미치면 가차 없이 **FAIL(반려)**합니다.

## Step 1. 정책서(`docs/POLICY.md`) 자동 합격표 검증
샌드박스에서 아래 자동 검사를 실행한다:
1. `python -m py_compile agent_core.py history_store.py pipeline.py app.py qa/run_once.py qa/eval_golden.py qa/benchmark_days.py qa/run_live_all.py`
2. `python qa/eval_golden.py` → `ALL TESTS PASSED` 확인
   - 골든셋 Drop 정확도 100% (`jfsweQpxqsY` 등 영역 불일치 강제 Drop)
   - 날조 인용 0건
   - 화장품법 제13조 절대 금지어 및 과대광고 적발 100%
   - 양방향 도메인(기초↔색조) 및 카피 3종 감사 통과
3. 보안 확인: 추적 파일 내 API 키(`AIza...`) 0건, 1페이지 보고서 원시 `<script>` 0건.

## Step 2. 데이터·신뢰도 기준 점검
1. 수집량: `'전체'`나 카테고리 조회 로직이 1~2건만 남고 잘리는 결함이 없는가?
2. 신뢰도 표시: S/A/B/C 바이럴 벤치마크 등급과 기준이 정직하게 표시되어 유저가 숫자의 의미를 바로 판단할 수 있는가?
3. 인사이트 품질: 프롬프트가 단순 단어 나열을 막고 `[연출/포맷 + 시청자 심리 + 반응 근거]` 45자 이상 문장을 요구하는가?

## Step 3. 사람 사용자 기준 검수 (조건부 브라우저 + UX 검수)
1. **실행 기준**: 레이아웃·CSS·새 화면/동선이 바뀐 마일스톤 끝에만 실제 브라우저(`1280×800`, `390×844`)를 **1회** 연다. 단순 문구·정규식·파이썬 백엔드 수정은 Step 1(Python + JS 1초 단위 검증)로 대체해 API·시간 낭비를 막는다.
2. **AI 한도 절약**: UI·레이아웃·동선만 확인할 때는 오프라인 기본 구조로 확인해 제미나이 API를 불필요하게 소모하지 않는다(프롬프트 수정 시에만 1회 실호출).
3. **검수 체크리스트 (토스 TDS · UX 라이팅 8원칙)**:

1. **첫인상 & UI/UX 유려함 (토스 TDS & 소비자 UX 가이드 기준)**
   - 데스크톱·모바일 모두에서 텍스트 깨짐, 가로 스크롤, 고정 바(sticky)가 본문 버튼이나 썸네일을 가리는 현상이 없는가?
   - 처음 열었을 때 시선이 자연스럽게 `1단계 → 2단계`로 흐르며, 2단계가 열렸을 때 중복 CTA 바가 사라지는가?
   - 여백, 정렬, 카드 계층이 답답하지 않고 유려한가?
2. **UX 라이팅 검증 (토스 8가지 원칙 기준)**
   - 화면 어디에도 개발자 용어(`2-Stage`, `velocity`, `json`, `localStorage`, `confidence`, 파일명 등)가 없는가?
   - 소리 내어 읽었을 때 번역투·수동형·군더더기 수식어 없이 바로 이해되는가? (`Easy to speak`, `Weed cutting`)
   - 다음 버튼을 누르면 무슨 일이 일어날지 예측되는가? (`Predictable hint`)
3. **직관적 이해 & 실제 문제 해결 (Jobs-to-be-Done)**
   - 처음 접속한 화장품 마케터가 **설명서 없이 10초 안에** 무엇을 눌러야 할지 아는가?
   - 이 결과만 보고 **유튜브를 따로 켜서 다시 뒤지지 않아도** 오늘의 트렌드 파악과 캠페인 초안 작성을 끝낼 수 있는가?
   - 실제 결과물(팀장 보고 요약 / 인플루언서 DM / 1페이지 보고서)을 **수정 없이 그대로 복사해 업무에 쓸 수 있는가?**
4. **불만 포인트 발굴**:
   - 통과(PASS)하더라도 다음 개선을 위해 **"사람 입장에서 아쉬운 점 2가지"**를 반드시 함께 적는다.

## 출력 형식
- **최종 판정**: `✅ PASS` 또는 `❌ FAIL (반려)`
- **Step 1~2 자동 검증 결과**: 통과/실패 요약
- **Step 3 사람 사용자 기준 검수 결과**: 1~3번 항목별 솔직한 평가
- **FAIL 시**: 파일명·위치·구체적 수정 지침을 `product-build`에 반려

# PLAYBOOK — 작업 방식 개선 기록

> 규칙: 매 루프 끝에 [틀린 가정 / 증거 / 고친 방법 / 다음 규칙]을 기록한다. 다음 루프 시작 전에 이 문서를 먼저 읽는다.

## 상시 규칙 (누적)
1. 기능이 돌아가는 것과 고객 문제가 풀린 것은 다르다. 결과 화면을 직접 읽고 마케터 입장에서 판단하기 전에는 완료라고 하지 않는다.
2. 제품·사실 정보는 출처 없이 쓰지 않는다. 출처 도메인과 확인 수준(confidence)을 같이 기록한다.
3. 브랜드 정보를 넣은 프롬프트에서 시장 트렌드를 뽑지 않는다. 팩트 추출과 브랜드 판정을 분리한다.
4. 모든 것에 높은 점수를 주는 결과는 실패로 본다. Drop 케이스가 통과해야 QA 통과.
5. 계획을 문서로 옮길 때 사용자가 승인한 내용을 요약하지 않고 그대로 보존한다.
6. 07:00 전에는 종료 선언을 하지 않는다. 기준 미달이면 미달로 보고한다.

## Loop 0 — 제품 진실 확보 (2026-11-25 01:30)
- 틀린 가정: 제품 문구를 그럴듯하게 써도 된다고 생각했다. 사용자가 준 URL을 읽지 않았다.
- 증거: 검색으로 확인한 결과 "7스킨", "올리브영 1위", "2.5mm 보습", "3중 레이어 거즈"는 근거를 찾지 못했다. 패드의 '2.5'는 이오시딘 2.5% 함유를 뜻한다.
- 고친 방법: `products.json`에 확인된 문구만 남기고 출처 도메인과 confidence=medium을 기록. 근거 없는 문구는 `unverified_removed_from_v1`로 분리.
- 한계: 공식 페이지 원문이 아니라 검색 요약 기반이다. 임상 수치(111.25%)는 시험 조건 확인 전에는 광고 문구로 쓰지 않는다.
- 다음 규칙: 코드의 제품 프리셋은 `products.json`에서만 읽는다. 하드코딩 금지.

## Sprint 1 — B2B 파이프라인 1차 구현 및 독립 QA (2026-11-25 01:55) — 판정: FAIL (반려)
- 틀린 가정:
  1. "금지 문구 리스트와 정규식 몇 개로 과대광고를 다 막을 수 있다"고 생각했다.
  2. "서브에이전트에서 `py_compile`도 unsandboxed로 돌릴 수 있다"고 가정해 60초 권한 타임아웃을 발생시켰다.
- 증거 (`docs/QA_REPORT.md`):
  1. `_brief_violations`가 `creator_note`의 주의사항을 위반으로 오탐(3건)하면서, `"올리브영 1등 / 3초 만에 즉각 진정 / 24시간 / 10배"`는 위반 0건으로 통과시켰다.
  2. `KBEAUTY_MEGA_KEYWORDS[:4][:3]` 이중 슬라이싱으로 기초 핵심 키워드 5개가 죽은 코드가 되었고 쿼터 33%를 색조에 낭비했다.
  3. 자막 없는 영상(`text_source="meta"`)이 Go 및 촬영 가이드까지 무경고 통과했고, `linked_claim`은 `"토너"` 2글자만 넣어도 통과했다.
  4. `creator_guide_md`에 개발자 파일명(`products.json`)이 노출되었다.

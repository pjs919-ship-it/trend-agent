> 규칙: 매 루프 끝에 [틀린 가정 / 증거 / 고친 방법 / 다음 규칙]을 기록한다. 다음 루프 시작 전에 이 문서를 먼저 읽는다.

## 상시 규칙 (누적)
1. 기능이 돌아가는 것과 고객 문제가 풀린 것은 다르다. 결과 화면을 직접 읽고 마케터 입장에서 판단하기 전에는 완료라고 하지 않는다.
2. 제품·사실 정보는 출처 없이 쓰지 않는다. 출처 도메인과 확인 수준(confidence)을 같이 기록한다.
3. 브랜드 정보를 넣은 프롬프트에서 시장 트렌드를 뽑지 않는다. 팩트 추출과 브랜드 판정을 분리한다.
4. 모든 것에 높은 점수를 주는 결과는 실패로 본다. Drop 케이스가 통과해야 QA 통과.
5. 계획을 문서로 옮길 때 사용자가 승인한 내용을 요약하지 않고 그대로 보존한다.
6. 07:00 전에는 종료 선언을 하지 않는다. 기준 미달이면 미달로 보고한다.
